Deployment Guide

質選所商店 — 上線部署指南

五個服務、一份 checklist。照順序走完全部就能上線。 所有 secret 只設在平台端的環境變數，不進這個 repo、不進任何檔案。

Cloudflare Pages ── 靜態前台 (dist/) + 後台 SPA │ 瀏覽器 islands 直打 API ▼ Railway (Go API) ──► Supabase PostgreSQL + Auth │ ├──► Cloudflare R2（圖床） └──► Resend（交易信）
1

Supabase PostgreSQL + Auth

申請 / 控制台

supabase.com/dashboard → 用 GitHub 登入即可，New Project 建一個專案（Region 選 Singapore 離台灣最近）。

要蒐集的資訊

值在哪裡拿設到
DATABASE_URLSECRET Project → Connect（右上）→ Transaction pooler 字串，密碼換成建專案時設的 DB password Railway + Pages build
SUPABASE_URL Project Settings → API → Project URL Railway + Pages + browser
SUPABASE_PUBLISHABLE_KEY 同頁 → Publishable key（舊版叫 anon key） Railway + Pages + browser
Transaction pooler 必加參數：若用 pooler（port 6543）字串，尾端要加 &default_query_exec_mode=simple_protocol — pgx 的 prepared statement 在 transaction 模式下需要它。用 direct connection（port 5432）則不用。

建管理員帳號

  • Authentication → Users → Add user → Create new user，填後台登入用的 email + 密碼。
  • 若要 Google / LINE 登入：Authentication → Sign In / Providers 開啟，OAuth client secret 設在 Supabase 後台（不是環境變數）。

Data API / RLS 開關（重要）

本架構是「瀏覽器 → Go API → Postgres」，沒有任何東西走 Supabase Data API（PostgREST REST API）。Go 後端用 DATABASE_URL 直連 postgres 協定；Supabase Auth（JWT 驗證）是獨立服務，不受這些開關影響。

開關（Project Settings → Data API）建議理由
Enable Data API關 整站不走 /rest/v1/，關掉直接消掉整面攻擊面
Automatically expose new tables關 自動對 anon/authenticated 授權新表 — migration 一建表就對外暴露，永遠手動控管
Enable automatic RLS開 防禦縱深：新表自動啟 RLS，誤開 Data API 時預設 deny-all。對 Go 後端無副作用（postgres 角色 bypass RLS）

Cloudflare R2 圖床

申請 / 控制台

dash.cloudflare.com → 註冊後左側 R2 Object Storage（需綁付款方式，免費額度內不收費）。

要蒐集的資訊

值在哪裡拿設到
R2_ACCOUNT_IDSECRET R2 Overview 右側的 Account IDRailway
R2_ACCESS_KEY_IDSECRET R2 → Manage R2 API Tokens → Create API token（Object Read & Write，指定 bucket）— secret 只顯示一次 Railway
R2_SECRET_ACCESS_KEYSECRETRailway
R2_BUCKET建的 bucket 名稱Railway
R2_PUBLIC_BASE_URL bucket → Settings → Public access：開 r2.dev 子網域，或綁自訂網域 Railway + Pages build
建議綁自訂子網域（如 img.你的網域）取代 r2.dev — 品牌一致、可過自己網域的快取規則。

Resend 交易信

申請 / 控制台

resend.com →

設定步驟

  • Domains → Add Domain：輸入你的網域，照畫面在 DNS（Cloudflare）加 SPF / DKIM 記錄，等 Verify。
  • API Keys → Create API Key（Sending access）。
值內容設到
RESEND_API_KEYSECRET建立的 API key（只顯示一次）Railway
RESEND_FROM質選所 <orders@你的網域>（網域須已驗證）Railway
CONTACT_NOTIFY_TO客服通知收件信箱Railway
沒設 RESEND_API_KEY 不會壞 — 通知會記成 log 不寄出，之後可在後台「通知日誌」一鍵重試。

Railway Go API

申請 / 部署

railway.app → New Project → Deploy from GitHub Repo → 選這個 repo。railway.toml 已配好 Docker build、部署前自動 migrate、/healthz 健康檢查。

Variables 分頁設這些

變數值
APP_ENVproduction
HTTP_ADDR:8080
SITE_ORIGINhttps://你的網域（CORS 單一來源，要跟 Pages 正式網域一致）
PUBLIC_SITE_URLhttps://你的網域
PUBLIC_API_BASEhttps://api.你的網域 或 Railway 給的 *.up.railway.app
DB_DRIVER / DATABASE_URLpostgres + Supabase DSNSECRET
AUTH_MODEsupabase
SUPABASE_URL / SUPABASE_PUBLISHABLE_KEY步驟 1 拿到的
SUPABASE_VERIFIER_MODEremote（預設；jwks 模式見文件取捨）
R2_* 五件步驟 2 拿到的SECRET
RESEND_* + CONTACT_NOTIFY_TO步驟 3 拿到的SECRET
EDGE_SECRETSECRET自己生一個 32+ 字元隨機字串，步驟 6 的 Transform Rule 用同一個
CF_DEPLOY_HOOK_URLSECRET步驟 5 在 Pages 建完 Deploy Hook 後回填
ECPAY_* 四件要上金流才設（見下方）；全留空就停用
部署完先驗證：curl https://<railway-domain>/healthz 回 200、 /api/products 回 200、Railway deploy log 裡 migrate 跑完。 API 網域建議在 Railway → Settings → Networking 綁 api.你的網域。

Cloudflare Pages 前台 + 後台

前台專案

Workers & Pages → Create → Pages → Connect to Git → 選 repo 與分支。

設定值
Build commandmake site（會照 SITE_THEME 建對的 theme bundle 再 render）
Output directorydist
環境變數APP_ENV=production、SITE_THEME=curatory、PUBLIC_SITE_URL、PUBLIC_API_BASE、R2_PUBLIC_BASE_URL、DB_DRIVER=postgres、DATABASE_URLSECRET（render 需要讀 DB）、Supabase 三件（AUTH_MODE/SUPABASE_URL/SUPABASE_PUBLISHABLE_KEY，這三個會進 browser bundle — 是公開值）

後台 SPA（第二個 Pages 專案）

設定值
Build commandnpm --prefix admin ci && npm --prefix admin run build:only
Output directoryadmin/dist
環境變數ADMIN_API_BASE=https://api.你的網域/api（結尾含 /api）、Supabase 三件
SPA 路由需要 admin/dist/_redirects 寫 /* /index.html 200 — 若檔案不存在請在 repo 補上。

Deploy Hook（發布迴路）

  • 前台 Pages 專案 → Settings → Builds & deployments → Deploy hooks → 建立，拿 URL。
  • 回填 Railway 的 CF_DEPLOY_HOOK_URL — 之後 tools/publish（後台發布動作）會 render → 上傳 dist → POST hook 觸發 Pages 重建。
6

網域 + 邊緣防護 Cloudflare DNS

  • 網域 DNS 託管到 Cloudflare（Registrar 買或把 nameserver 指過來）。
  • 前台網域：Pages 專案 → Custom domains → 綁 你的網域。
  • API 網域：api.你的網域 CNAME 到 Railway，且該 host 走 Cloudflare proxy（橘雲）。
  • Transform Rule 注入 edge secret：Rules → Transform Rules → Modify Request Header → 對 api.你的網域 的請求 Set header X-Edge-Secret = Railway 的 EDGE_SECRET 值。之後直接打 Railway origin 的請求一律 403 — 擋掉繞過 Cloudflare WAF 的流量。
輪換順序：先在 edge 設新值 → 再改 Railway 的 EDGE_SECRET → 確認後把 edge 舊規則清掉。/healthz 已豁免，Railway healthcheck 不受影響。

ECPay 綠界 選配 — 要上金流才做

廠商後台 vendor.ecpay.com.tw → 測試環境：vendor-stage.ecpay.com.tw

  • 廠商後台 → 系統開發管理 → 介接設定：拿 MerchantID / HashKey / HashIV。
  • Railway 設 ECPAY_ENVIRONMENT（stage/production）+ 三個 key。SECRET
  • ReturnURL / PaymentInfoURL 要指到 https://api.你的網域 的 ECPay callback 路由 — 在廠商後台或 API 參數設定。
上線前務必用 stage 環境完整跑一筆交易，確認 callback 對帳與訂單狀態轉移。
